# Responsive margins, Sapienza and installation

- Margin drawings are bounded by the actual space beside the 1010px main area,
  not enlarged with a fixed breakpoint. Browser checks at 1366, 1575, 1920 and
  2560px left positive gaps between the parabola and the configuration panel.
- Sapienza sends no selected subject, requires equal counts across all five
  subjects and interleaves them. In AI mode the validator rejects a missing or
  unbalanced subject and uses the balanced demo bank. The client also rejects
  incomplete semester responses. Original question order is kept between server
  delivery and grading so answer indexes stay aligned.
- The browser walkthrough covered all five subjects in a five-question Sapienza
  attempt. Automated checks cover 5/10/15/20 questions and a 20-question API request
  with an irrelevant `subjectId: agil`.
- Manifest and service worker are scoped to `/ingegno/`. Icons include 192/512px,
  a maskable 512px version and an Apple 180px icon, generated by the checked-in
  PowerShell script from the existing paper/G/flag identity.
- The install button uses the browser prompt when available and otherwise shows
  platform guidance. iPhone/iPad guidance uses Safari's Share / Add to Home Screen.
  It is hidden in standalone mode. Installing on an actual phone still needs a
  physical-device check; desktop viewport emulation does not prove mobile install.
- Only known public UI resources are cached. API responses, POST requests,
  outside origins and sibling apps are never intercepted. Online reads prefer
  current files; cached files support the offline demo bank. Server-backed exams
  still need connection for grading and AI always needs connection.
- Updates do not call skipWaiting or reload an active exam. Cache cleanup only
  removes this app's `genio-shell-` caches. No existing user data is removed.
- The browser recognized the manifest without errors and the worker activated
  locally (the page displayed its offline-ready status). Offline fallback and
  API/cache isolation have automated service-worker tests.

References: https://web.dev/learn/pwa/installation and
https://web.dev/learn/pwa/web-app-manifest .
